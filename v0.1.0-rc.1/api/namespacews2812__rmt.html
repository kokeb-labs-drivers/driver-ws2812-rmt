constexpr Result< uint32_t > ResolveRmtRate (uint32_t source_hz, uint32_t requested_hz, uint32_t tolerance_ppm=1000U) noexcept
 The tick rate an ESP32 RMT channel really runs at, computed as ESP-IDF v5.5 does (rmt_common.c): the channel divider is rounded to the nearest integer, (clock + request / 2) / request, so the real rate can be above or below the request. On the targets with a group prescaler (all but the ESP32 and ESP32-S2) the group prescaler is the first from 1 up that brings that divider into 1 to 256; on the ESP32 and ESP32-S2 the divider is the rounded one directly, which gives the same rate whenever it is at most 256 (every request above source_hz / 256).

◆ kMinResolutionHz

constexpr uint32_t ws2812_rmt::kMinResolutionHz = 20'000'000
inlineconstexpr

The lowest tick rate the driver accepts for a named variant: below 20 MHz some profile has a window edge within 10 ns of its value (V5 sits exactly on one at 16 MHz and below, docs/timing.md); Variant::Custom is not limited.

◆ kRecommendedResolutionHz

constexpr uint32_t ws2812_rmt::kRecommendedResolutionHz = 20'000'000
inlineconstexpr

The tick rate to prefer: 50 ns ticks leave margin on every window (ambiguity A-5); a finer rate (40 MHz, 80 MHz) keeps the same margins.
