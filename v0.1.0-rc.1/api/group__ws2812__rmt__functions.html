◆ ResolveRmtRate()

constexpr Result< uint32_t > ws2812_rmt::ResolveRmtRate ( uint32_t  source_hz,
uint32_t  requested_hz,
uint32_t  tolerance_ppm = 1000U 
)
constexprnoexcept

The tick rate an ESP32 RMT channel really runs at, computed as ESP-IDF v5.5 does (rmt_common.c): the channel divider is rounded to the nearest integer, (clock + request / 2) / request, so the real rate can be above or below the request. On the targets with a group prescaler (all but the ESP32 and ESP32-S2) the group prescaler is the first from 1 up that brings that divider into 1 to 256; on the ESP32 and ESP32-S2 the divider is the rounded one directly, which gives the same rate whenever it is at most 256 (every request above source_hz / 256).

Parameters
source_hzThe source clock in hertz.
requested_hzThe tick rate asked for.
tolerance_ppmThe largest deviation accepted, in parts per million.
Returns
The real rate, or TimingUnreachable when a rate is 0, no divider reaches the request, or the real rate is more than tolerance_ppm from the request.

◆ ResolveWaveform()

constexpr Result< Waveform > ws2812_rmt::ResolveWaveform ( const Timing &  timing,
uint32_t  resolution_hz,
uint32_t  reset_us 
)
constexprnoexcept

Turn a timing into ticks at the port's real tick rate.

Each of the four durations gets the tick count nearest its nominal that lies inside its window (windows inclusive); a bit period below period_min_ns is repaired by lengthening the low, and a period above period_max_ns or an empty window is TimingUnreachable. The reset is reset_us (0: the minimum plus kResetMarginUs), never at or below the minimum, which is a strict bound.

Parameters
timingA valid timing (see Config::custom).
resolution_hzThe tick rate the port reported, 1 to kMaxResolutionHz.
reset_usThe reset low time, 0 for the default, at most kMaxResetUs.
Returns
The waveform, TimingUnreachable when no tick count fits (or the arguments are out of range).

◆ Validate()

constexpr Result< void > ws2812_rmt::Validate ( const Config &  config,
size_t  capacity 
)
constexprnoexcept

Check a configuration against a strip capacity without touching hardware. Pure and constexpr, so a fixed configuration can be proved with static_assert.

Rejected: an unknown variant or gamma; a custom timing on a named variant, or an inconsistent one on Custom; an order that is invalid, does not match the variant's channel count, or is missing on Custom; a reset_us that is not above the variant's minimum or above kMaxResetUs; a pixel count above the capacity or a capacity of 0 or above kMaxPixels; a settle or slack above its maximum.

Parameters
configThe configuration.
capacityThe pixel capacity of the driver object.
Returns
Ok or InvalidArgument.
