Detailed Description

template<Ws2812RmtPort Port, size_t PixelCapacity>
requires detail::NonZeroSize<PixelCapacity>
class ws2812_rmt::Ws2812Rmt< Port, PixelCapacity >

Driver for one strip of up to PixelCapacity single-wire addressable LEDs.

Lifecycle: construct with the configuration (no I/O), then EnsureInitialized(), the one way to start; then set pixels and call Show(). Show() and CurrentWaveform() return NotInitialized until EnsureInitialized() has succeeded; the pixel setters only store.

Optional hooks: bool GpioSet(CtrlPin, GpioSignal) (the strip supply; without it PowerOn() and PowerOff() return Unsupported; with it the strip starts unpowered, and Show() and TraceWire() are refused with NotPowered until the first successful PowerOn() and again after PowerOff()), void Log(LogLevel, const char*).

Concurrency: one owner task per strip; no locking, never from an interrupt. Memory: PixelCapacity pixels of 4 bytes plus PixelCapacity x 4 wire bytes live inside the object, so give it static storage on a small stack.

Template Parameters
PortYour class derived from GpioInterface<Port>.
PixelCapacityThe most pixels the strip object holds, 1 to kMaxPixels.

template<Ws2812RmtPort Port, size_t PixelCapacity>
Result< void > ws2812_rmt::Ws2812Rmt< Port, PixelCapacity >::EnsureInitialized ( )
noexcept

Start the driver, once: the only way to initialise it.

Validates the configuration (no I/O on failure), lets the port create its channel, asks the port for its real tick rate and resolves the waveform inside the datasheet windows. After it succeeds later calls return Ok at once with no I/O; after it fails the driver stays uninitialised and the next call starts again from the beginning.

Returns
Ok, InvalidArgument (Validate() failed), Bus (the port could not start or report a rate) or TimingUnreachable (no tick count fits a window at that rate).

◆ Show()

template<Ws2812RmtPort Port, size_t PixelCapacity>
Result< void > ws2812_rmt::Ws2812Rmt< Port, PixelCapacity >::Show ( )
noexcept

Encode the pixels (gamma, then brightness, in the wire order) and send them, blocking until the frame and the reset are out. One pass, no allocation. A failed send leaves the pixels intact and the driver usable; the next Show() or TraceWire() first waits a full reset through DelayUs(), so a half frame the failure left in the pixels is latched and cannot shift the next one.

With a GpioSet() hook it is refused (NotPowered) and nothing is sent until the first successful PowerOn() and again after PowerOff(): a driven DIN on an unpowered strip back-feeds it (docs/hardware.md).

Returns
Ok, NotInitialized or NotPowered (no port call is made), or Bus (the port's Transmit() failed, timed out or underran where the port can see it; an underrun it cannot see returns Ok, see docs/contract.md).
